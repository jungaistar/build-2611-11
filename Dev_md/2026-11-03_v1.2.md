# 2026-11-03 v1.2 — 실제 설비 이름으로 설비군 판정 (기획자 댓글 2)

## 왜
v1.1 배포 뒤 기획자가 패들릿 댓글로 실제 설비 이름을 알려 왔다(원문은 CLAUDE.md 부록 C).
- 가공설비 10대: 호리젠탈 · 135 NC · 150NC · 130NC(1호기)~(4호기) · MCT · 5호 밀링 · 110NC
- 용접설비 20대: MAIN · BOOM · TRACK · SUB · CHASSIS · ARM · BUCKET · BLADE 의 N호기
- v1.1 이름 판정(로봇 · ROB · 용접 · ABB · KOBE · 야스카와 …)으로는 **용접 20대가 전부 가공으로 잘못 잡혔다** — 「MAIN 1호기」에 용접 낱말이 하나도 없어서다. 실측: `['MAIN 1호기','BOOM 2호기'].map(autoGroup)` → `['mach','mach']`.
- 설비 라인 이름일 뿐 개인정보 · 실적 값이 아니라 코드 · 테스트 · 범례 시트에 그대로 썼다. 예제 데이터의 설비 이름(NC-01 · 용접로봇-01 …)은 가짜 값 표시를 지키려고 바꾸지 않았다.

## 한 일
- 엔진 `js/downtime.js`
  - `judgeName(name)` → `{ group, sure, why }`. 용접 낱말 = 종전 `WELD_RE` + 용접 라인 8개(`WELD_LINE_RE`, 영문 낱말은 앞뒤에 영문자가 없을 때만 — WARM · SUBSTATION · TRACKER 에 걸리지 않게; 띄어쓰기 · 대소문자 · 「호기」 무관). 가공 낱말 = `MACH_RE`(NC · CNC · MCT · MILLING · HORIZONTAL · MACHINING · LATHE 같은 경계 규칙 + 밀링 · 호리젠탈 · 머시닝 · 선반).
  - 용접만 → 용접, 가공만 → 가공, **둘 다 → 확인 필요**(`sure:false`, 가공으로 셈), 둘 다 없음 → 가공. `autoGroup()` 은 `judgeName().group` 이라 호출부는 그대로.
  - `judgeGroup(name, S)` — 기준 설정에서 고른 값이 있으면 `src:'setting'`, 아니면 이름 판정(`name` / `ambiguous`). 화면 · 확인할 것용.
  - 기록에 `groupSrc`(form / auto)를 남기고, `analyze()` 에서 양식의 설비군 칸 · 기준 설정으로 정해지지 않은 대상 중 판정이 확인 필요인 이름을 **확인할 것에 대상 이름으로 한 번** 올린다(「이름에 가공 · 용접 낱말이 둘 다 있어 설비군을 정하지 못했습니다 — 지금은 가공설비로 셉니다 …」).
  - `PLANNER_EQUIP`(30대, 댓글 순서 그대로) · `withPlannerEquip(equipGroups)` — 이미 있는 이름은 덮어쓰지 않고 `{ equipGroups, added, total }` 을 돌려준다.
  - 범례 시트(`legendRows`) 맨 아래에 「기획자 설비 목록(2026-11)」 30줄(이름 · 설비군). 설비군 설명 줄에 새 판정 낱말.
